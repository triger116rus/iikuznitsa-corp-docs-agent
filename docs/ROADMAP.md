# План развития ИИ-агента по регламентам

В спринте главным было решить задачу концептуально: три кейса заказчика работают на его данных от начала до конца,
с проверкой качества и эксплуатацией. Ниже — задел на развитие при наличии времени и ресурсов: для каждого пункта —
зачем, как сделаем и оценка. Каждое изменение агента — с контрольным прогоном обоих наборов вопросов до и после
(`eval/run_eval.py`).

## 1. Качество ответа

- **Контролёр полноты.** Главный источник ошибок слепого набора — неполный ответ при верном пункте (названа часть
  условий перечня) и соседний пункт той же темы после уточнения подразделения. Второй короткий вызов модели сверяет
  ответ с пунктом: все ли условия названы; при пропуске — дописать или оговорка. Включать на GPU: на CPU +20–40 с.
- **Карточки норм.** При загрузке модель раскладывает пункт на структуру «кто — делает что — при каком условии —
  в какой срок — исключения» (таблица рядом с текстом). Полнота перечня проверяется по карточке, противоречие
  разъяснения и регламента — по полям, ответы «кто / срок» — без генерации. Загрузка 611 пунктов на CPU ≈ 1,5–2 ч один раз.
- **Контекст пункта, сгенерированный моделью** (contextual retrieval): к пункту при индексации — 1–2 предложения
  «о чём он в документе» (сейчас — название документа и раздела). Пункты-продолжения находятся по смыслу раздела.
- **Самообучение на кейсах ошибок.** Каждый сбой («неверно», «Это другой вопрос», письмо в службу качества, когда
  ответ в регламентах был) — карточка кейса: вопрос, ответ агента, верный ответ, причина (поиск, перечень, синоним,
  порог, подразделение), ревью «проверено / не проверено». Проверенный кейс автоматически становится контрольным
  вопросом — набор растёт из реальных вопросов сотрудников; агент предлагает исправление (синоним, правка пункта,
  порог), применяется после ревью и прогона. Разбор — локальной моделью ночью (тексты регламентов наружу нельзя);
  облачной модели — только обезличенная выгрузка (`app/diag.py`). Оценка — 1–2 дня.
- **Настройка смыслового кэша по статистике.** Порог подобран на 21 паре вопросов; журнал хранит каждое
  срабатывание и отметки «Это другой вопрос» — по ним порог и правила сверки уточняются на реальной нагрузке.
- **Уточнение ситуации помимо подразделения** (кто клиент, какая сделка) — сейчас решает модель, отдельно не проверялось.

## 2. Доступ и безопасность

- **Доступ к регламентам по подразделениям и ролям.** Сейчас любой сотрудник может спросить о любом регламенте
  (подразделение из учётной записи — только область ответа по умолчанию). У документа — список групп с доступом
  из AD (по умолчанию — вся компания) и уровень:
  - «закрытый» — название видно, содержание нет: «ответ, вероятно, есть в регламенте „…", у вас нет доступа —
    запросить?»; запрос — владельцу документа (служба качества в копии), решение — сотруднику письмом;
  - «скрытый» — даже название закрыто: вопрос уходит в службу качества как вопрос без ответа.

  Пункты недоступных документов не попадают в модель, «где искать», граф, разъяснения и кэш (ключ кэша — с учётом
  прав, иначе ответ «утечёт» через кэш); запросы к закрытым документам — в журнал как статистика для владельца.
- **Вход через AD/SSO**, роли из групп каталога.
- **Подлинность ответа службы качества** средствами почты (DKIM/SPF, заголовок Authentication-Results) — сейчас по
  адресу отправителя; ответ не от службы качества идёт в базу только после её подтверждения.
- **Обезличивание выгрузки локальной моделью** распознавания имён и организаций (сейчас — шаблоны, ловят не всё);
  автоматический разбор выгрузки облачной моделью с отчётом обратно.
- **Аудит в SIEM** — экспорт журнала действий (для банков и КИИ).

## 3. Источники и каналы

- **Единая модель документа** для любого источника: тип (регламент, приказ, FAQ, вики), статус, область действия,
  даты вступления, владелец, доступ. Открывает следующие пункты.
- **Confluence, PDF (со сканами), сетевые папки**; массовая загрузка **существующих FAQ службы качества**.
- **Бот в мессенджере** (Dion и др.) поверх API чата — нужна служебная авторизация бота.
- **Дополнение внешними источниками** (законодательство, лицензируемые виды деятельности) — по ответу заказчика
  необязательная часть: наружу только текст вопроса, внешнее — отдельным блоком «Не из регламентов компании».
- Направление — агент как точка входа ко всем знаниям компании; при росте корпуса до сотен документов —
  графовые сводки (GraphRAG) и иерархические сводки (RAPTOR) для обзорных вопросов.

## 4. Процесс службы качества

- **Объединение повторных писем**: одинаковый вопрос без ответа присоединяется к открытому запросу, а не порождает новое письмо.
- **Напоминание** при просрочке ответа; **маршрутизация** вопросов вне регламентов по темам (кадры, бухгалтерия).

## 5. Скорость, масштабирование, поставка

- **Ответ за секунды** — GPU (модели ≈ 19 ГБ); узкое место измерено: 82 % времени — модель (вкладка «Аналитика»).
  План — лёгкой моделью (−8–9 с на CPU) только после прогона.
- **Горизонтальное масштабирование и поставка как код.** Архитектура готова: состояние — в PostgreSQL, модель
  и эмбеддинги — по OpenAI-совместимому API (за балансировщиком без изменения кода). Осталось:
  1. почтовый опрос — в одной копии приложения (блокировка в PostgreSQL), иначе ответ заберут дважды;
  2. лимиты писем и попыток входа — в базу (сейчас в памяти копии);
  3. загруженные DOCX — в базу или общее хранилище;
  4. развёртывание как код: балансировщик (nginx), копии приложения, серверы модели и эмбеддингов, PostgreSQL;
     вариант для GPU; подъём на новом сервере одной командой.

  Оценка — 1–1,5 дня с нагрузочной проверкой и восстановлением «с нуля». Копии модели на одном CPU-сервере не
  ускоряют (делят ядра) — выигрыш от второго сервера или GPU.
- **Порядок выкатки «тест → приёмка → бой»**: новая модель, пороги или редакции регламентов сначала проходят
  контрольный прогон на тестовом экземпляре, затем выкатываются.

## 6. Пилот у заказчика

Пакет пилота на 2–4 недели: загрузка корпуса заказчика, 50–100 его реальных вопросов как контрольный набор, перемер
порогов, отчёт «до / после» (доля вопросов без службы качества, 95-й перцентиль времени, ноль ответов без цитаты),
расчёт окупаемости по калькулятору.
